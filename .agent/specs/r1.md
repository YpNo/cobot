# Spec — release 1 (`partner` 0.1.0)

size: large · profile: library · owner: YpNo · date: 2026-11-06 · source: docs/02-design.md §3–§15

## Principles check
Proportional (one plugin, no new dependency), rules before autonomy (gate first, tested first),
knowledge is a skill, proof not promises, learn write little. Nothing global (ADR-0003).

## Stories and acceptance
1. As the owner, in a repo with the plugin loaded, every outward command is judged by the layered
   rules (default < owner < project) and `/partner:rules show|check|explain|sync` tell me why.
   Accept: the pytest bypass table (design §13) is green; `explain "rtk git -C x push"` names the rule and layer.
2. As the owner, a session starts with a brief (≤ 10k chars: protocol + CONTEXT head + verified
   commands + last two journal entries + open findings + rule counts), only when the repo is trusted.
   Accept: `partner-session` output on this repo ≤ 10k; on a cloned repo with a planted `.agent/` the brief says "untrusted, not loaded".
3. As the owner, `/partner:onboard` fingerprints a repo and writes CONTEXT, JOURNAL, FINDINGS (or
   foreign mode); `/partner:spec` writes one spec with ≤ 5 clarify questions that carry options and a
   recommendation; `/partner:build` runs tasks with focused tests and proof lines; `/partner:wrap`
   converges, runs the full set, fans out reviews, writes the journal entry with a verified stamp.
   Accept: the four evals pass at threshold 1.0 on this machine.
4. As a builder, I receive my task and my language skill and never commit or write `.agent/`.
   Accept: `rust-builder`, `go-builder` frontmatter; `builder-routing` behaviour checked by hand in R1 (eval in R1.1).
5. As the owner, language and GitHub Actions knowledge is current and dated.
   Accept: every version in `lang-*`/`expert-gha` has a `[verified YYYY-MM-DD · src]` line; no number without one.

## Clarify (answered by the design or defaults; owner may override)
- Q1 Agent scope token: `@name` suffix on a rule line → default yes.
- Q2 Owner identities file: `~/.claude/partner/identities` (one `host/owner` per line) → default; onboard offers to create it with the current remote's owner.
- Q3 Brief size split: protocol ≤ 3k, memory ≤ 6k → default.
- Q4 Eval model: pinned in CI, unpinned locally → default.
- Q5 `sync` output: prints a JSON fragment and a unified diff against `~/.claude/settings.json`, never writes → default.

## Contracts

### Rule file (`rules/default.rules`, `~/.claude/partner.rules`, `.agent/partner.rules`)
```text
# comment
never Bash(git push --force*)
ask   Bash(git push*)            @builder      # optional agent scope: applies only to that agent_type
allow Bash(cargo test*)                        # owner layer only; project layer: never/ask only
never Edit(~/.claude/settings*.json)
ask   mcp__*__create*
```
Matching: `Bash(pattern)` is fnmatch over the normalised segment **and** over `(binary subcommand …)`
after stripping wrappers (`rtk env command exec nohup time`), assignments, and global options of
known binaries (`git -C x -c k=v`, `terraform -chdir=x`, `gh -R x`, `kubectl -n x --context x`,
`gcloud --project x`, `docker -H x`). Opaque runners (`sh bash zsh python python3 node make just
mise task npm pnpm yarn cargo xtask eval xargs`, `$(…)`, backticks, `sudo`) → `ask`, unless the owner
layer allows the exact command line (then silence). `Edit|Write|MultiEdit|NotebookEdit(path)` match
`file_path` (with `~` expanded, repo-relative also tried). `mcp__server__tool` matches the tool name.
Precedence: `never` in any layer wins; else an owner-layer `allow` silences the gate (Claude Code's
own permissions still apply); else `ask` from any layer; else silence. Across segments the most
restrictive verdict wins. Project layer `allow` is ignored with a warning. Also normalised: path
prefix on the binary, `timeout`/`nice`/`ionice`/`stdbuf`/`flock` prefixes, combined short flags on
`git push`, `+refspec`, `gh api` method anywhere, heredoc bodies skipped, `$`-led binaries opaque.
A shell token naming a file protected by a `never` Edit/Write rule → `ask`. Agent scope matches
with or without the `partner:` prefix. The gate log records tool, decision and the first 120 chars.

### Hook input/output
Input: Claude Code PreToolUse JSON (`tool_name`, `tool_input`, `cwd`, `agent_type`?). Output: silence,
or `hookSpecificOutput.permissionDecision` `ask|deny` with a ≤ 200-char reason `partner rule: <line> (<layer>)`.

### Brief (`partner-memory brief`)
Blocks in priority order, each capped, the whole truncated to the budget: CONTEXT head (profile,
goal, constraints, verified commands; ≤ 2 500 chars) · last two journal entries by `## YYYY-MM-DD`
heading regardless of position, each ≤ 1 200 chars keeping heading, `Open`, `Next` before `Proof`
· open findings count and last three rows (floor 400 chars) · knowledge topics and open specs.
Measured on the 1 013-line cartridge-os journal, not only on this repo. Legacy `.agent/` (CONTEXT,
ARCHITECTURE, JOURNAL) read unchanged.

### Trust
Trusted when **every** remote's `host/owner` (as written in the URL, case-folded) is in
`~/.claude/partner/identities`; or `.agent` is a symlink whose resolved path equals the external
memory path derived from `origin`; or the repository's root-commit hash is listed in
`~/.claude/partner/trusted` (outside the repo, so a clone cannot plant it; onboard appends it after
the owner's yes). Otherwise the brief carries one line and loads nothing. When `origin/HEAD` exists
and `.agent/` differs from it, the brief says so in one line. Accepted risk (R1): "not loaded" is
advisory for the model's own `Read` of `.agent/*`; the protocol forbids it, no hook enforces it.

### Knowledge line
`- [verified 2026-11-06 · src: <url or exp: cmd>] claim` · also `reported`, `assumed`. Lives in
`skills/<x>/references/*.md` (plugin) and `.agent/knowledge/<topic>.md` (project, ≤ 80 lines).

### Journal entry
`## YYYY-MM-DD — title` then `Changed:` `Why:` `Proof:` `Open:` `Next:`; wrap adds `verified: <sha> · <commands>`.

### Findings
`| F-nn | seen | observation | goes to |` in `.agent/FINDINGS.md`; wrap triages.

### Knowledge skill (`lang-<x>`, `expert-<x>`)
Frontmatter: `name`, `description` (≤ 1 536 chars, names the paths and the moment), `paths:` globs,
`user-invocable: false`. Body ≤ 150 lines: toolchain and commands with verified versions, idiom
(current, opinionated, short), tests (naming `unit_scenario_expected`), security specifics,
pitfalls, "do not". `references/` holds the dated versions table and longer material.
`consult-<x>`: `context: fork`, `agent: partner:consultant`, `user-invocable: true`; body = the audit
procedure and the report shape (≤ 10 findings: severity · file:line · fix · confidence; `knowledge_delta`).

## Trade-offs
- Argv matching for a handful of known binaries, fnmatch for the rest: full shell semantics are out
  of reach; the aim is honest and careless attempts, not obfuscation (ADR-0001).
- `learn --promote` and `compact` are R1.1: R1 proves the format and the project layer first.
- Evals in R1 run locally and on manual dispatch only: each run is a paid Claude session.
