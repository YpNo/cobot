# Spec — R2: hardening, the UI expert, CI/CD and cloud experts

size: large · profile: library · owner: YpNo · date: 2026-11-07 · slices: four, one branch and one PR each

## Goal

R2 makes the cobot's proof mechanical where R1 relied on the protocol's word, measures what the
sessions cost, and widens the bench: a UI/UX expert for web interfaces and constrained devices
(the owner's request, with Google Stitch reachable through its MCP server under the gate), the
CI/CD family beyond GitHub Actions, then Google Cloud, Kubernetes and the service mesh. What does
not change: outward actions still go through `git` and `gh` under the gate, MCP write tools ask,
knowledge lines carry a status and a source, the agent listing stays under 600 tokens, the
SessionStart payload under 10 000 characters.

## Principles check (slice 1)

- Proportionality: three Python additions (`cobot-rules report`, `cobot-memory stamp`,
  `cobot-usage`), one hook entry, two eval cases, skill text; no new dependency.
- Rules before autonomy: the report check blocks a builder's stop with a reason the builder can
  act on, never the owner's own turn; the stamp predicate enriches an `ask`, it never turns one
  into a `deny`; `cobot-usage` reads local transcripts only and prints counts, never content.
- Proof: unit tests on the hook payloads and on fixture transcripts; the evals run under the
  owner's subscription; a dogfood session on headscale shows the stamp reason on `git push`.
- Delivery: tasks below are the commits; one PR per slice; slices stack on each other's tip when
  the previous PR is not merged yet, with the base set to that branch.

## Stories and acceptance (slice 1)

1. **A builder report without proof never reaches the orchestrator as accepted.** A
   `PostToolUse` hook on the `Agent` tool (`hooks/report.sh` → `cobot-rules report`) acts only
   when `tool_input.subagent_type` matches `^cobot:(builder|.*-builder)$`; it reads
   `tool_response.content`, the delivered report (also the one a `SubagentHandback` delivers, so
   there is no closing-text ambiguity and no in-subagent matching). The report contract in every
   builder prompt becomes exact: under `Checks:`, one line per command as
   `` - `<command>` → exit <n> `` with the output tail indented below, or the single line
   `Checks: none — <reason>` for a task with nothing to run (docs-only, command denied by the
   gate). The parser accepts a `Checks:` block with at least one backticked command and an exit
   marker (`exit <n>`, `exit code <n>`, `→ <n>`) anywhere in the block, or the `none — <reason>`
   form; anything else is blocked with `{"decision": "block", "reason": "builder report lacks
   command and exit code under Checks:; re-run the task and require each check as `<command>` →
   exit <n> with its output tail, or `Checks: none — <reason>`"}`. The block reaches the
   orchestrator, which re-spawns with the reason (one re-spawn instead of a continued turn; no
   loop guard needed, the orchestrator decides). Consultant, challenger and learner reports are
   not checked by this hook. The hook fails open on a malformed payload (logs and exits 0): a
   report hook must never strand a session; `report.sh` is its own shim with exit 0 on failure,
   unlike `gate.sh`. Acceptance: pytest fixtures for a passing report, a `none —` report, a
   report without exit codes, a non-builder subagent, a malformed payload; one live builder
   run on this repository shows the accepted report.
2. **`git push` tells the owner whether the tree was wrapped.** `cobot-memory stamp` parses the
   last journal line matching `^verified: ([0-9a-f]{7,40})(\+working-tree)?( · .*)?$`, resolves a
   short sha with `git rev-parse --verify <sha>^{commit}`, and returns `ok <sha>` when the stamp
   equals HEAD, or when every commit from the stamp to HEAD touches only `.agent/**`, `docs/**`,
   `CHANGELOG.md`, `README.md` (committed mode), or when the stamp equals HEAD in foreign mode;
   a `+working-tree` stamp returns `missing — stamp taken on a dirty tree; wrap after the last
   task commit`; no stamp returns `missing — no verified stamp`. The output is hex and fixed
   phrases only, never a journal line, and the journal is read through the same trust check as
   the brief (an untrusted clone's journal is repository content). The gate, on a `git push`
   that is `ask`, appends `stamp: ok <sha>` or `stamp: missing — <phrase>; run /cobot:wrap` (≤ 60
   chars) to its reason. `wrap` step 6 now says: HEAD must be clean except `.agent/`; never write
   `+working-tree`; `contribute` and `ship` call `cobot-memory stamp` instead of re-implementing
   the check. Acceptance: tests for the three `ok` cases, the dirty-tree stamp, the missing
   stamp and the untrusted journal; the gate's explanation line in a dry run on this repository
   (whose historic stamps are all `+working-tree`, so it reads `missing` until the next wrap).
3. **The owner can see what a session cost across sessions.** Claude Code's `/usage` shows the
   live session with attribution to skills, subagents and plugins; `cobot-usage` adds history
   (every session of this repository, dated) and a journal-ready line, which is what a routing
   decision needs (design §10). `cobot-usage [--since DATE] [--session ID]
   [--json]` reads the transcripts of the current repository under
   `~/.claude/projects/<slug>/` (main transcripts and subagent transcripts), sums
   `input_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens` and `output_tokens`
   once per request (rows deduplicated on `requestId`, falling back to `message.id`: a request
   streams several `assistant` rows that repeat the same usage), per model, per agent type (the
   `<session>/subagents/agent-<id>.jsonl` files, typed by the `agentType` field of the sibling
   `agent-<id>.meta.json`, else "orchestrator"), per session, plus a count of `Skill` and
   `Agent` calls by name (token attribution per skill is not computable from a tool-use row and
   is not claimed); prints at most 40 lines, never message text; `--json` for the journal.
   Sessions started from worktrees live under `<slug>--claude-worktrees-*`, so the glob is
   `<slug>*` and the report names each folder it read. The slug is derived from the
   repository root the way Claude Code does (non-alphanumeric characters → `-`, honouring
   `CLAUDE_CONFIG_DIR`). The transcript format is documented as internal and changeable, so the
   parser keeps only `type == assistant` rows with a `message.usage` object, sums what it
   recognises and reports the rows it skipped. Acceptance: a fixture
   transcript with two models, one subagent and one skill call gives known totals; the real
   repository prints without error.
4. **Contribute carries what headscale taught.** `onboard` in foreign mode writes, for every
   remote except `origin`, two project-layer lines into the external memory's `cobot.rules`:
   `never Bash(git push <remote>*)` and `never Bash(git push *<url-path-stem>*)` (the URL form);
   `expand_push_flags` in the gate hoists option tokens (`-u`, `--tags`, `-o <x>`) after the
   remote so `git push -u ghsa fix` is seen as `git push ghsa …`; `contribute` records the list
   under `never push to:` in `UPSTREAM.md` when it creates the file and refuses to draft when
   `cobot-memory stamp` says missing, naming the command. Acceptance: tests on the rules written
   and on the hoisting; headscale's `ghsa` remote denied in a dry run in both forms.
5. **Two evals arrive.** `foreign-onboard`: the fixture is a git repository whose `origin` is
   `https://github.com/example-upstream/demo.git` (no identity of the owner), the case's `env`
   sets `XDG_DATA_HOME` to a path under the workspace so `init --foreign` never writes into the
   owner's data directory, the prompt is `/cobot:onboard --foreign` (no question to answer), and
   the graders are `tool_used Bash input_match "init --foreign"`, `tool_order` that call before
   any Edit or Write, and `regex` on the last message for `foreign mode` and `info/exclude`; the
   symlink and exclude facts themselves stay covered by pytest. `actions-pinning`: fixture
   workflow with `actions/checkout@v4`; the answer names a 40-hex pin from
   `expert-gha/references/actions.md` or says it must be re-resolved with `gh api` when the
   reference is stale, and mentions zizmor; `tool_used` Edit ≤ 1. Acceptance: both cases load
   and score ≥ 0.9 in the with-arm over three runs under the owner's subscription.

## Decision 27 (drafted here, confirmed by the challenger pass)

A UI/UX expert joins the bench as `expert-ui` (knowledge: design tokens, type scale, WCAG 2.2
AA, responsive and input modes, component systems; device profiles for constrained screens such
as the Miyoo Mini Plus at 640×480 with D-pad input and OnionOS themes) with `consult-ui` as its
read-only audit. Google Stitch is used through its official MCP endpoint
(`https://stitch.googleapis.com/mcp`, API key in the `X-Goog-Api-Key` header, registered by the
owner with `claude mcp add … -s user`, never shipped in the plugin's `.mcp.json` because the key
and the quota are the owner's); the gate's default layer gains `ask mcp__*__generate*` and
`ask mcp__*__edit*` beside the existing create, update, delete, merge and push patterns, so the
rule holds whatever name the owner gives the server; list and get tools stay silent. Design §12
gains the sentence: design artefacts in the owner's own SaaS account may be created through MCP
under `ask`; code and repository writes still go through `git` and `gh`. The expert works without Stitch: it produces the
design brief, the token sheet and the review; Stitch, when present, renders screens from that
brief. Verified today from third-party write-ups and Google's codelab; the official docs page
does not render for a fetch, so the endpoint and the tool list are `reported` until the owner's
first live call confirms them.

## Risks

- A blocked report costs a re-spawn, not a continued turn: accepted, because the orchestrator
  (not the builder) owns the decision and no loop guard is needed; `SubagentStop` was the
  alternative and lost on the handback ambiguity and the asked-once guard it would need.
- A builder's honest "the command was denied by the gate" is `Checks: none — denied by the
  gate: <command>`; the parser accepts it, the orchestrator reads the reason.
- Transcript format drift: `cobot-usage` tolerates unknown rows and reports the count it
  skipped.
- Stitch quotas and terms are the owner's; the expert never calls a generate tool without the
  owner's yes (the gate's `ask`).

## Challenger

SOUND WITH CHANGES (2026-11-07), six majors and three minors, all folded: the stamp format wrap
really writes (`<short sha>+working-tree`, no separator) and its dirty-tree meaning; the
handback ambiguity and the missing asked-once guard, both removed by moving the check to
`PostToolUse` on `Agent`; the undefined report shape, now exact in every builder prompt with a
`none — <reason>` form; usage rows repeated per request, subagent typing through `meta.json`,
skills as counts, the worktree slug glob; the foreign-onboard eval writing into the owner's data
directory, now `env`-isolated and grading the decision; push-flag hoisting and the URL form of
a remote; server-name-independent MCP patterns and the §12 sentence; stamp output restricted to
hex and fixed phrases behind the trust check. Checked clear: no interference with the gate
matcher or the consultant and learner forks, no `Stop` for the orchestrator, gate timing,
foreign-mode stamp, slicing against decision 20, `deep-review` deferral against §11.

`deep-review`, the switch plan, the public-day settings, any version bump.
