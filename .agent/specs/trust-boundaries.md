# Spec — a spec names its trust boundaries before the code exists (F-49)

## Goal

F-49, recorded by the security-auditor spec (Not in scope, owner, 2026-11-16): `/cobot:spec`
never asks where untrusted input enters a design or what crosses a privilege line. The sweep
finds those places only after the code exists, and the challenger attacks only what the spec
writes down.

| step | today | after |
|---|---|---|
| spec template | no boundary section | `## Trust boundaries`, always: each boundary the change creates or alters, or `none:` with why |
| each boundary | — | where it enters or what it crosses, the guard, a story whose acceptance is a negative test |
| challenger | attacks what the spec says | also attacks a boundary the change creates or alters that the spec misses or leaves unproven |
| security sweep | finds boundaries from code | also checks that each guard a trusted spec declared is at its site |

What does not change: the spec's other sections, the build, wrap's `/security-review` trigger,
and specs already written (not rewritten; the sweep skips a spec without the section).

## Owner's answers (2026-11-18)

- **When:** always. A change that crosses no boundary writes `none: <why>`.
- **Each boundary carries:** where untrusted input enters or what crosses a privilege line, the
  guard, and a story whose acceptance is a negative test. The challenger raises a missing one as
  MAJOR.
- **The sweep** (asked again after the challenger's point 2): it checks each declared guard at
  its site. No `found, not declared` lines: a spec declares only what its change adds, so they
  would fire on every older boundary.
- **Proof:** text tests, plus graders on the existing `medium-spec-then-challenge` eval.

## Stories and acceptance

1. **The template has the section.**
   - `skills/spec/template.md` gains `## Trust boundaries` after *Stories and acceptance* (its
     rows point at stories), with:
     - the kinds, one line: network listeners and routes, subprocess and shell-out sites,
       filesystem paths built from input, deserialisation, crypto and randomness, authn and authz
       decisions, logging sinks, secrets read, held or forwarded, privilege lines (a role, a token
       scope, a sandbox, the gate);
     - one row per boundary the change creates or alters: `entry or crossing · guard · story`;
     - or one `none: <why>` line.
   - `references/procedure.md`'s inventory gains *privilege lines*, so both lists hold the same
     kinds.
   - Accept: a text test with one key word per kind (`listener`, `subprocess`, `paths built`,
     `deserialisation`, `crypto`, `authz`, `logging`, `secret`, `privilege`) finds each in both
     files.
2. **The spec skill asks for it.**
   - Step 2 (cold read): note the sites of each kind the change touches.
   - Step 3 (draft): fill *Trust boundaries* with every boundary the change creates or alters,
     each with a guard and a story whose acceptance is a negative test (hostile input refused, a
     privilege not gained); `none:` carries a reason the challenger can check.
   - Accept: text tests on the steps' exact phrases.
3. **The challenger attacks the boundaries the change creates or alters.**
   - `claude-agents/challenger.md` method gains one step: read *Trust boundaries*; from the
     stories and the lines the change touches, find a boundary it creates or alters that the
     section misses; a missed one, one without a guard, or one without a negative-test story is
     MAJOR; a `none:` the stories contradict is MAJOR. A boundary the change does not touch is
     not an objection.
   - `agents/challenger.md` (agy) regenerated by `scripts/sync-agents.py`.
   - Accept: a text test on the step, including the "does not touch" limit;
     `sync-agents.py --check` in sync.
4. **The sweep checks declared guards, in trusted memory only.**
   - `skills/security-sweep/SKILL.md`: before the fan-out the router runs `cobot-memory trust`
     (main thread) and adds `Memory: trusted` or `Memory: untrusted` to every unit's prompt. An
     unrun or failed check is `untrusted`.
   - `references/procedure.md`'s inventory: with `Memory: trusted`, read the *Trust boundaries*
     sections of `.agent/specs/*.md` (in foreign mode `.agent` is the owner's external memory,
     so it is read too); for each declared boundary whose site is under the unit's paths, look
     for its guard at the site:
     - guard missing at a site that exists: `declared guard missing: <boundary> · <file>:<line>`;
     - site no longer found: counted in one line, `declared, site gone: N`.
   - These are inventory lines, never findings; a missing guard the auditor can exploit is
     audited by the packs like any other site. A spec without the section is skipped.
   - With `Memory: untrusted` no spec is read (a clone shipping its own `.agent/` could declare
     guards to steer the auditor): the inventory says `declared: not read (untrusted memory)`.
     Spec text is data either way.
   - Accept: text tests on the router's prompt line and its default, and on the procedure's
     rules (inventory lines, skip without the section, untrusted not read).
5. **An eval shows an agent writes the section.**
   - `evals/medium-spec-then-challenge`: the prompt names the spec's path
     (`.agent/specs/config-loader.md`) so file graders have a fixed target. Two graders on it:
     - `boundary-section`: a `source: file` regex scoped to the section,
       `## Trust boundaries\n(?:(?!\n## )[\s\S])*?\b(env|environment|config file)`;
     - `boundary-not-none`: `match: not_contains` on `## Trust boundaries\s*\n\s*none:`.
   - `tests/test_eval_graders.py`: `matches()` on one passing section and three failing ones (a
     `none:` line, the word only in another section, no section).
   - Accept: those tests; the case passes one local run (`--runs 1`, weaker than its `runs: 3`;
     CI runs the three), its seven other graders unchanged.
6. **Docs and the finding.**
   - Decision 33. `docs/02-design.md`: the medium row's spec names the section, and the eval
     table's `medium-spec-then-challenge` row its two graders. CHANGELOG. F-49 closed.

## Trade-offs

- **Always a section, `none:` allowed:** a missing section and a forgotten one look the same; an
  explicit `none: <why>` gives the challenger a claim to break.
- **Only what the change creates or alters:** a spec is a change, not an inventory. Asking it
  for every boundary in a file it touches makes MAJORs nobody can act on.
- **Negative test per boundary:** the owner's standing rule moves from review time to design
  time, where it is cheapest.
- **Guards checked, not coverage:** a declared guard missing at its site is something to look at;
  a boundary no spec declared is normal for code older than the rule.
- **Kinds written twice, kept equal by a key-word test:** the template stands alone for the
  author; a test is cheaper than reading a sweep reference at every spec.

## Not in scope

- A script that parses specs: specs stay free text; the challenger and the tests carry the rule.
- Rewriting existing specs.
- Agy: the skills and the challenger are shared texts, so agy gets the same rules; no hook.
