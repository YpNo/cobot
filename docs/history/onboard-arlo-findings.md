## Wrong or awkward (skill/tool — what happened — what should happen)
1. onboard step 1 (refresh skips to step 4) — init never runs, so a legacy memory gets no FINDINGS.md and its CONTEXT.md keeps no `profile:` / `forge:` / `governance:` lines (legacy had prose `Profile: \`service\``). Step 5 doesn't say to add the missing header fields. Should: refresh runs `init` (it never overwrites) and lists the template header fields missing from CONTEXT.md.
2. cobot-memory brief / CONTEXT template order — with a 108-line CONTEXT (under the 120 cap) the brief dropped Verified commands and Constraints, because the template puts Environment first and cap_sections drops from the tail. The CONTEXT budget also shrinks as journal entries grow: a long onboard entry dropped Constraints again. Fixed here by reordering and trimming by hand. Should: template order header → Stack → Verified → Constraints → Environment, or cap_sections drops by priority, not position; onboard step 5 checks `brief` still carries Verified + Constraints.
3. cobot-memory trim_entry — sorts body lines one by one, so multi-line fields (legacy layout `Changed:  ...` plus indented continuation lines) are split: the first line moves up, the continuation lines stay behind under another field. The brief shows a garbled entry. Legacy field names (Seen, Tests, Verified, Not done, Owner) aren't ranked either. Should: group continuation lines with their field before ranking.
4. cobot-deps rust adapter — runs `cargo update --dry-run --verbose --workspace`. `--workspace` updates only workspace members, so every semver-compatible update comes back as `Unchanged X (available: Y)` and is labelled "(outside the requirement)", which is wrong. A line like `Unchanged arlo-rs v0.4.0 (requires Rust 1.99.1)` matches neither regex, so arlo-rs 0.4.0 -> 0.4.1, the key dependency, is missed. A plain `cargo update --dry-run --verbose` locks 58 packages. Should: drop `--workspace`, and handle the "requires Rust" form.
5. cobot-deps advisories — reports 4 (cargo-deny). `cargo audit` finds 5: deny.toml ignores nothing, and RUSTSEC-2026-0383 (webpki-root-certs) is missing from cargo-deny's output, probably a staler advisory DB. Should: say which DB and how old it is, or take the union with cargo-audit when it's installed.
6. cobot-memory findings add `--goes-to X` — any value other than empty or "open" counts as closed, so a parked finding drops out of the brief at once. The help doesn't say so. Should: `--goes-to` records routing only, and closure goes through `findings close`; or the help states the rule.
7. cobot-memory compact `--summary` — when the summary has its own `Proof:` line, compact appends a second `Proof: raw entries in JOURNAL-archive.md`. Should: use `Archive:`, or merge into the summary's Proof.
8. cobot-memory help — the `stamp` line sits between `init` and init's description ("create CONTEXT, JOURNAL, FINDINGS ... never overwrites"), so that description reads as stamp's.
9. onboard step 4 (run every candidate command) — no guard on cost. Here / was 92% full with no target/, so a fresh GStreamer+BoringSSL workspace build might not fit. Should: check free disk and whether target/ exists before build commands, and ask.
10. CONTEXT verified table — it has only a `verified` date, but step 4 says to keep the exit code. cargo deny and cargo audit ran and failed with exit 1; legacy commands that weren't re-run have no slot (a prose paragraph was used). Should: a result column (exit code or pass/fail), plus a "carried over, not re-run (last run: date, source)" form.
11. governance takes a path, not a section — the principles here are CONTRIBUTING.md's "Non-negotiable rules" section, but /cobot:spec will treat the whole file (branches, commits, PR rules) as principles. Should: accept `path#anchor`, and spec reads only that section.
12. Legacy agent files are invisible — check and brief ignore .agent/HANDOFF.md (12.6K, the richest design memory). The brief tail mentions only ARCHITECTURE.md. Onboard has no step for a root CONTEXT.md, WORKFILE.md, CLAUDE.md, GEMINI.md or .agents/rules, which here contradict .agent/ (SSE/DASH design, a different clippy line, the rust-build container). Should: the brief tail lists other .agent/*.md as "read on demand"; onboard reads the repo's agent-facing files and parks contradictions as findings.
13. onboard and the journal compact — onboard doesn't mention compact, though check warns about it. Should: on a refresh, offer `compact --summary` when check warns.
14. onboard step 6 says the allow lines make the verified commands "silent for the gate". The gate was already silent ("no rule matched"); the lines matter only to `/cobot:rules sync` (settings permissions). Commands wrapped in `distrobox enter rust -- bash -lc '...'` can't be covered usefully either. Should: reword the step, and say how wrapped (container) commands are handled.
