# Home Assistant — the REST and WebSocket APIs, tokens and hass-cli

Format: `- [verified YYYY-MM-DD · src: <url>] claim`. The gate's view of `hass-cli` is in the
skill's *A live instance under the gate*.

## APIs and tokens

- [verified 2026-11-21 · src: https://contributors.home-assistant.io/core/internals/rest-api/] REST API is served at `/api/` (trailing slash) on the frontend port: 8123 by default, 80 under the Supervisor. Every request needs the Authorization header with the Bearer scheme. 401 means unauthorized. The `api` integration loads whenever the frontend does.
- [verified 2026-11-21 · src: https://contributors.home-assistant.io/core/internals/websocket-api/] WebSocket API is at /api/websocket. On connect the server sends auth_required. The client answers with a message of type auth carrying the access token in its access_token field. The server replies auth_ok, or auth_invalid with a message, then disconnects. In the command phase every client message carries an `id` that increases with each command, echoed in the reply. A ping gets a pong, not a result.
- [verified 2026-11-21 · src: https://contributors.home-assistant.io/core/internals/auth-api/ ; https://www.home-assistant.io/docs/authentication/ ; https://github.com/home-assistant/core/blob/dev/homeassistant/auth/models.py] Long-lived access tokens are created on the user profile under Security and are valid for 10 years. Normal access tokens last expires_in 1800 s, and unused refresh tokens are removed after 90 days. The core RefreshToken model has a `user` field and no scope field, so a long-lived token acts with its user's full rights.

## hass-cli

- [verified 2026-11-21 · src: https://github.com/home-assistant-ecosystem/home-assistant-cli/blob/1.0.0/homeassistant_cli/cli.py ; https://github.com/home-assistant-ecosystem/home-assistant-cli/tree/1.0.0/homeassistant_cli/plugins] hass-cli 1.0.0 commands: area, completion, config, device, discover, entity, event, ha (Supervisor), info, integration, map, raw, service, state, system, template. Environment variables: HASS_SERVER (default `auto`), HASS_TOKEN (falls back to HASSIO_TOKEN), HASS_SUPERVISOR_TOKEN, HASS_PASSWORD, HASS_CERT. click auto_envvar_prefix is HOMEASSISTANT. Flags: --insecure, --timeout, --debug.
- [verified 2026-11-21 · src: https://github.com/home-assistant-ecosystem/home-assistant-cli/tree/1.0.0/homeassistant_cli/plugins ; https://github.com/home-assistant-ecosystem/home-assistant-cli/blob/1.0.0/homeassistant_cli/remote.py] hass-cli 1.0.0 verbs that write to the instance: area create/delete/rename; device assign/rename/delete; entity assign/rename/delete/enable/disable; event fire; integration reload/delete/enable/disable; service call; state edit/delete/toggle/turn_on/turn_off; raw post and raw ws (any message type); the Supervisor POSTs under `ha` (core restart/stop/start/rebuild/update/options/check, host reboot/shutdown/reload/options, supervisor/os/dns/multicast/cli update, addons/store/backup reload, among others). Read-only: config, info, system log/health, state get/list/history, event watch, discover, map, the list/info verbs, raw get. `template` renders on the server via POST /api/template unless --local is given.
- [verified 2026-11-21 · src: https://github.com/home-assistant-ecosystem/home-assistant-cli/blob/1.0.0/homeassistant_cli/helper.py ; https://github.com/home-assistant-ecosystem/home-assistant-cli/blob/1.0.0/homeassistant_cli/config.py] In hass-cli 1.0.0, `--debug` calls debug_requests_on(). That sets http.client HTTPConnection debuglevel to 1 and puts root and urllib3 logging at DEBUG. Configuration __repr__ prints only yes or no for whether an access token and an API password are set.
- [verified 2026-11-21 · src: exp: python3 -c "import http.client, inspect; print(inspect.getsource(http.client.HTTPConnection.send))" (Python 3.13.15)] At debuglevel 1, `http.client.HTTPConnection.send` prints every block it sends with `print("send:", repr(data))`, the request headers included, so `hass-cli --debug` prints the Authorization header.
