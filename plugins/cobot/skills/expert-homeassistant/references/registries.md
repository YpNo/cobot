# Home Assistant — the registries and ZHA

Format: `- [verified YYYY-MM-DD · src: <url>] claim`. Every write below needs an admin user and,
through `hass-cli raw ws`, asks at the gate. Zigbee radio and protocol facts beyond ZHA as an
integration wait for `expert-iot-protocols`.

## Device, entity, area, floor and label registries

- [verified 2026-11-21 · src: https://github.com/home-assistant/core/tree/dev/homeassistant/components/config (device_registry.py, entity_registry.py, area_registry.py, floor_registry.py, label_registry.py)] Registry WS read commands: config/device_registry/list (+ list_linked_devices, list_composite_splits), config/entity_registry/list, list_for_display, get, get_entries, get_automatic_entity_ids, settings/get, config/area_registry/list, config/floor_registry/list, config/label_registry/list.
- [verified 2026-11-21 · src: https://github.com/home-assistant/core/tree/dev/homeassistant/components/config] Registry WS write commands, all require_admin: config/device_registry/update, remove, remove_config_entry; config/entity_registry/update, remove, settings/update; area and floor: create, update, delete, reorder; label: create, update, delete (no reorder).
- [verified 2026-11-21 · src: https://github.com/home-assistant/core/blob/dev/homeassistant/components/config/device_registry.py] config/device_registry/update takes device_id plus optional area_id, labels, name_by_user, disabled_by; via the API disabled_by accepts only "user" or null.
- [verified 2026-11-21 · src: https://github.com/home-assistant/core/blob/dev/homeassistant/components/config/entity_registry.py] config/entity_registry/update takes entity_id plus optional aliases, area_id, categories, device_class, icon, labels, name, new_entity_id (rename), disabled_by, hidden_by.
- [verified 2026-11-21 · src: https://github.com/home-assistant/core/blob/dev/homeassistant/helpers/entity_registry.py and helpers/device_registry.py] Entity disabled_by values: config_entry, device, hass, integration, user. hidden_by values: integration, user. Device disabled_by values include config_entry, device (parent disabled), integration, user.
- [verified 2026-11-21 · src: https://github.com/home-assistant/developers.home-assistant/blob/master/docs/entity_registry_index.md] Only entities with a unique_id are stored in the entity registry. The registry key is (platform, integration domain, unique_id); entity_id is the user-renamable handle; the user must not be able to change unique_id.
- [verified 2026-11-21 · src: https://www.home-assistant.io/faq/unique_id] An entity without a unique_id cannot be renamed, have its settings changed, be deleted, get Assist aliases or get a category from the UI.

## ZHA

- [verified 2026-11-21 · src: https://github.com/zigpy/zha/blob/dev/zha/application/const.py ; https://github.com/home-assistant/core/blob/dev/homeassistant/components/zha/manifest.json] ZHA RadioType: ezsp (Silicon Labs, bellows), znp (TI Z-Stack, zigpy-znp), deconz (ConBee/RaspBee, zigpy-deconz), ziggurat (Rust host stack, zigpy-ziggurat), zigate (zigpy-zigate), xbee (zigpy-xbee). Core pins zha==2.4.3 and zha-quirks==2.4.1.
- [verified 2026-11-21 · src: https://www.home-assistant.io/integrations/zha] ZHA docs recommend the Home Assistant Connect ZBT-2 (ezsp). Radio migration in the UI supports ezsp, znp and deCONZ (firmware 0x26700700 or later). On znp, zigate and xbee, Green Power devices work only through routers.
- [verified 2026-11-21 · src: https://github.com/home-assistant/core/blob/dev/homeassistant/components/zha/websocket_api.py] ZHA WS read commands: zha/devices, zha/device, zha/devices/groupable, zha/groups, zha/group, zha/devices/clusters, .../clusters/attributes, .../clusters/commands, .../clusters/attributes/value (reads from the device over the air), zha/devices/bindable, zha/configuration, zha/network/settings, zha/network/backups/list. Every ZHA WS command is require_admin.
- [verified 2026-11-21 · src: https://github.com/home-assistant/core/blob/dev/homeassistant/components/zha/websocket_api.py ; https://github.com/home-assistant/core/blob/dev/homeassistant/components/zha/services.yaml] ZHA WS write commands: zha/devices/permit, zha/devices/reconfigure, zha/topology/update, zha/devices/bind and unbind, zha/groups/bind and unbind, zha/group/add and remove, zha/group/members/add and remove, zha/configuration/update, zha/network/backups/create, zha/network/backups/restore, zha/network/change_channel. No WS remove command: removal goes through the zha.remove service or config/device_registry/remove_config_entry.
- [verified 2026-11-21 · src: https://github.com/home-assistant/core/blob/dev/homeassistant/components/zha/__init__.py and const.py] ZHA YAML (zha:) keys: enable_quirks (default true), custom_quirks_path (must be an existing directory), device_config, zigpy_config (a dict passed to zigpy). usb_path, baudrate and radio_type are deprecated.
- [verified 2026-11-21 · src: https://github.com/zigpy/zigpy/blob/dev/zigpy/quirks/v2/__init__.py ; https://github.com/zigpy/zha-device-handlers/blob/dev/zhaquirks/builder/builder.py ; gh api repos/zigpy/zha-device-handlers/releases/latest] The quirks v2 API moved to zha-device-handlers as zhaquirks.builder.QuirkBuilder (applies_to, replaces, add_to_registry). Importing from zigpy.quirks.v2 is deprecated and only a shim. Latest zha-quirks release is 2.4.1 (2026-11-04).
- [verified 2026-11-21 · src: https://github.com/zigpy/zigpy/blob/dev/zigpy/config/defaults.py ; https://www.home-assistant.io/integrations/zha] zigpy network backups are on by default every 24 h (zigpy_config backup_enabled, backup_period in minutes, default 1440). Manual backups are under Settings > Network Settings; migration is via Settings > Connectivity > Zigbee > Migrate, which takes an automatic backup first.
- [verified 2026-11-21 · src: https://github.com/zigpy/zigpy/blob/dev/zigpy/config/__init__.py ; https://github.com/home-assistant/core/blob/dev/homeassistant/components/zha/update.py ; https://www.home-assistant.io/integrations/zha] ZHA OTA is on by default (zigpy ota.enabled default true). Updates appear as standard update entities (INSTALL, SPECIFIC_VERSION, PROGRESS, BACKUP, RELEASE_NOTES features). Providers are configured under zigpy_config ota: extra_providers (type, url, path, index_file, manufacturer_ids, override_previous) and disable_default_providers.
