# Terraform / IaC rule pack

Loads for `.tf` and `.tfvars` files, including module code. Rule ids are `TF-<CAT>-<nn>`. IaC has no injection
surface to speak of; its risk is granted privilege, exposed surface and state. Rate by what an attacker gains,
not by exploitability of the HCL itself.

## State & secrets

- **TF-STATE-01** `terraform.tfstate` or `*.tfstate.backup` committed. State holds every attribute in plaintext,
  including generated passwords, keys and certificates. CRITICAL.
- **TF-STATE-02** Local backend for shared infrastructure: no locking, no encryption, no audit. Use a remote
  backend with encryption and DynamoDB/GCS locking.
- **TF-STATE-03** Remote backend without encryption at rest, or a state bucket that is public, unversioned or
  lacks access logging.
- **TF-SEC-01** Credential literal in `.tf` or a committed `.tfvars`: provider keys, DB passwords, tokens. CRITICAL.
- **TF-SEC-02** Variable holding a secret without `sensitive = true`: it prints in plan output and CI logs.
- **TF-SEC-03** `output` exposing a secret without `sensitive = true`; a sensitive output consumed by a
  non-sensitive one.
- **TF-SEC-04** Secret generated by `random_password` and stored only in state, never rotated, with no
  secret-manager resource.
- **TF-SEC-05** `.gitignore` not covering `*.tfstate*`, `.terraform/`, `*.tfvars` (except examples), `crash.log`,
  `override.tf`.

## Identity & permissions

- **TF-IAM-01** Policy with `Action: "*"` and `Resource: "*"`, `roles/owner`, `roles/editor`, or `Contributor` at
  subscription scope. Rate by scope: broad at org level is CRITICAL.
- **TF-IAM-02** Trust policy with `Principal: "*"` or a cross-account principal with no `ExternalId`/condition:
  confused deputy.
- **TF-IAM-03** `iam:PassRole`, `iam:CreatePolicyVersion`, `sts:AssumeRole` on `*`, or `allUsers` /
  `allAuthenticatedUsers` GCP bindings: each is a path to privilege escalation.
- **TF-IAM-04** Long-lived access keys (`aws_iam_access_key`, `google_service_account_key`) where workload identity
  federation / IRSA / managed identity would work. The key material also lands in state.
- **TF-IAM-05** Service account with no condition or scope narrowing, reused across environments.

## Network exposure

- **TF-NET-01** Security group / firewall rule with `0.0.0.0/0` (or `::/0`) on ingress. On 22, 3389, 3306, 5432,
  6379, 27017, or `-1`/all ports it is CRITICAL: an open management or database port.
- **TF-NET-02** Storage made public: S3 `acl = "public-read"`, missing `aws_s3_bucket_public_access_block`, GCS
  `allUsers` binding, Azure container with public access.
- **TF-NET-03** Database or cache instance with `publicly_accessible = true`, or placed in a public subnet.
- **TF-NET-04** Kubernetes control plane endpoint public with no authorized-CIDR restriction.
- **TF-NET-05** Load balancer or listener with HTTP (no TLS), a TLS policy permitting below 1.2, or a managed cert
  not enforced.
- **TF-NET-06** Default VPC/subnet used, or default security group modified rather than a purpose-made one.

## Data protection

- **TF-DATA-01** Encryption at rest not enabled, or a provider-managed key where a CMK is required: RDS, EBS, S3,
  GCS, disks, snapshots.
- **TF-DATA-02** Backups disabled, retention at the minimum, or `skip_final_snapshot = true` on a production database.
- **TF-DATA-03** `deletion_protection = false` / no `prevent_destroy` lifecycle on stateful or irreplaceable resources.
- **TF-DATA-04** Versioning off on a state or data bucket; no lifecycle policy.
- **TF-DATA-05** Logging/audit disabled: CloudTrail, VPC flow logs, GCP audit logs, storage or LB access logs.

## Provider & module supply chain

- **TF-SUP-01** Provider without a version constraint, or a pessimistic constraint loose enough to admit a major bump.
- **TF-SUP-02** `.terraform.lock.hcl` not committed: provider binaries are not pinned by hash.
- **TF-SUP-03** Module sourced from a git branch, an unpinned registry version, or an HTTP URL. Pin to a tag or
  commit SHA.
- **TF-SUP-04** Module from an unvetted third-party namespace with access to credentials: a module runs provider
  calls with your privileges, and `external`/`local-exec` provisioners run arbitrary code on the operator's
  machine or CI runner. Treat those two as CRITICAL by default.

## Correctness hazards

- **TF-HAZ-01** `local-exec`/`remote-exec` provisioner used for something a resource should do: non-idempotent,
  invisible to plan, and unwound on destroy in unpredictable order.
- **TF-HAZ-02** `count`/`for_each` on a value not known at plan time (apply breaks); `count` on a list causes
  index-shift recreation of unrelated resources.
- **TF-HAZ-03** `depends_on` papering over a missing implicit dependency, or a genuine ordering left implicit.
- **TF-HAZ-04** Hardcoded region, account id, project id or environment name in a reusable module.
- **TF-HAZ-05** `ignore_changes` on a security-relevant attribute: drift in exactly the field that matters goes unseen.
- **TF-HAZ-06** Provider block inside a module (prevents reuse and pins the caller's provider configuration).
- **TF-HAZ-07** No `validation` block on a variable whose bad value produces a confusing mid-apply failure.

## Verification commands (read-only)

```bash
terraform fmt -check -recursive
terraform validate                 # requires init; skip if offline
tfsec .                            # if installed
checkov -d . --framework terraform # if installed
trivy config .                     # if installed
grep -rn '0.0.0.0/0\|"\*"\|publicly_accessible\|allUsers' --include='*.tf' .
grep -rn 'sensitive' --include='*.tf' . | head
git ls-files | grep -E '\.tfstate|\.tfvars$'
```
